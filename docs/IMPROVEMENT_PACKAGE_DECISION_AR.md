# دراسة حزمة التحسين المقترحة — قرار قبل التنفيذ

**تاريخ المراجعة:** 23 أغسطس 2026  
**نطاق الدراسة:** لا تغييرات وظيفية. جرى فحص محتوى الأرشيف وملف قرار 2.5D ومقارنتهما بمسار «غرفة الملابس» الحالي واختباراته.

> **الخلاصة:** الحزمة مفيدة من ناحية الرؤية البصرية، لكن لا ينبغي دمجها كدفعة واحدة. المسار الأنسب هو تحسينات محلية صغيرة ومتدرجة تحافظ على: **رفع الصورة ← التفريغ المحلي ← قالب الاستديو ← التنزيل/المشاركة**. أما أي إضافة تخفي القالب، أو تضاعف الأيقونات، أو تدّعي زوايا غير موجودة للقطعة، فتؤجل أو ترفض في هذه المرحلة.

## 1. ما الذي احتوته المرفقات؟

| المصدر | ما جرى فحصه | النتيجة |
|---|---|---|
| أرشيف `ClothGenPro_حزمة_تحسين_للمطور.zip` | 48 ملفاً، منها 5 وثائق عربية، وحزمة خلفيات SVG وأيقونات فئات | حزمة مواصفات وأصول خفيفة؛ لم يُشغّل أي ملف من الأرشيف ولم يُدمج أي أصل في المشروع. |
| ملف `ClothGenPro_تحسينات_مخصصة_v3_قرار_2_5D.xlsx` | 9 أوراق: النطاق، قرار 2.5D، الخلفيات، الجودة، العرض، القوالب المصغرة، طلب المطور، الأولويات، المراجع | يوصي بمعالجة محلية و2.5D بصري، ويؤجل 3D الحقيقي وAR وImage-to-3D. |

الحزمة تقترح أربع مجموعات عمل: **تحسين الجودة والحواف**، **مكتبة خلفيات حسب الفئة**، **عرض 2.5D بصري**، و**قوالب رئيسية مع صور مصغرة**. كما تقترح عدم جعل أي خدمة خارجية أو GPU أو نموذج 3D شرطاً للتدفق الأساسي.

## 2. ما هو موجود بالفعل في غرفة الملابس؟

| المجال | المنفذ حالياً | أثره على القرار |
|---|---|---|
| التفريغ | إزالة خلفية محلية، وحدود بكسلات مرئية، وحماية من قص القطعة أو الشخص | قاعدة جيدة، ولا يُستبدل النموذج أو مساره بلا مقارنة حقيقية. |
| التنقيح | ممحاة، استعادة، عصا لون، Lasso، حذف شفاف، تراجع، وضبط سطوع/تباين/تشبع محلي | يغطي جزءاً عملياً من التنظيف وضبط اللون؛ لا حاجة لاستوديو جديد. |
| الاستديو | خلفيات كاملة: نظيف/دافئ/بارد/إضاءة؛ ظل: بلا/ناعم/أرضي؛ تكبير آمن | يطابق أساس توصية 2.5D البسيطة بالفعل. |
| القالب | مقاسات 1:1 و4:5 و3:4 و9:16 و1.91:1، مع النص والسعر الاختياريين | يحقق شرط تعدد النسب من الحزمة، ولا يحتاج إعادة بناء القالب. |
| المشاركة | تنزيل، إرسال الصورة فقط، واتساب مع النص التسويقي | يجب ألا يتغير بسبب أي تحسين بصري. |
| الواجهة | شريط أدوات أفقي ولوحات عائمة قصيرة وإغلاق بالنقر خارجها | يمنع تحويل الحزمة إلى لوحة خيارات طويلة أو أيقونات إضافية بلا ضرورة. |

## 3. قرار كل اقتراح

| الاقتراح | الحكم | السبب وشرط التنفيذ |
|---|---|---|
| تنظيف هالة الحواف، نقاط القناع، وهامش أمان | **مناسب — P0** | له أثر مباشر على الجودة. يضاف داخل **تعديل الصورة** أو تلقائياً فقط بعد مقارنة قبل/بعد واختبارات لقطعة سوداء وبيضاء ومنقوشة. لا يبدّل مسار التفريغ الحالي بلا قياس. |
| تحذير دقة أو ضبابية الصورة | **مناسب — P0** | يمكن تقديمه كتلميح صغير قبل التفريغ، لا كعائق يمنع الرفع. يستفيد من محلل الجودة المحلي الموجود. |
| ضبط الإضاءة والتباين وحماية اللون | **مناسب بشروط — P1** | الموجود يتيح ضبطاً يدوياً. التحسين التلقائي يجب أن يكون محدوداً وقابلاً للتراجع، ولا يغير لون القماش أو الشعار بصمت. |
| Denoise وSharpen وUpscale | **مؤجل — P1** | مفيد للصور الضعيفة، لكنه عالي المخاطر على النقشة والنصوص ويستهلك الهاتف. لا يدخل قبل اختبار صور واقعية ومقارنة واضحة. |
| 25 خلفية مصنفة حسب الفئة | **مناسب لاحقاً — P1** | الأصول SVG خفيفة، لكن إضافتها كلها في الواجهة الآن ستزيد التعقيد. إن اعتمدت، تُرفع كأصول ثابتة خارج المستودع وتحمّل عند اختيارها، مع تصنيفات قليلة لا قائمة طويلة. |
| أيقونات فئات نسائي/رجالي/بناتي/ولادي/مواليد/شبابي | **مناسب لاحقاً — P1** | تصلح كاختيار اختياري داخل أداة الخلفية، لا كتصنيف تلقائي يدعي معرفة القطعة من دون تحقق. |
| منصة، منتج عائم، انعكاس، أرضية بمنظور | **مناسب كتجربة بصرية اختيارية — P2** | ينسجم مع الظل الأرضي الحالي. يضاف لاحقاً تحت خيار واحد بسيط مثل «عرض: استديو / عائم / منصة»، وليس كـ3D حقيقي. |
| Parallax لمس | **مؤجل — P2** | لا يحسن ملف التصدير نفسه وقد يربك لمس الأدوات على الهاتف. |
| صور مصغرة مشتقة من الصورة نفسها | **غير مناسب كافتراضي** | يزاحم القطعة الرئيسية ويتعارض مع هدف الواجهة البسيطة. إن أضيف لاحقاً يكون قالب عرض منفصلاً لا يغير القالب الأساسي. |
| صور مصغرة بزوايا ±45° | **غير مناسب حالياً** | التدوير البصري لا ينشئ زاوية حقيقية للقطعة. قد يوهم المستخدم بوجود تفاصيل لم توفرها الصورة. |
| 360 أو Multi-angle | **مؤجل** | يحتاج صوراً حقيقية متعددة الزوايا من المستخدم؛ لا يستخرج بصدق من صورة واحدة. |
| GLB/GLTF وAR وImage-to-3D | **مرفوض في المرحلة الحالية** | يغيّر هدف المشروع، يحتاج أصولاً أو خدمات جديدة، وقد يخمن الخلف والجانب والنقشة. |
| خدمات AI خارجية أو GPU أو API | **غير مناسب لهذه الحزمة** | الحزمة نفسها لا تجعلها مطلوبة. المشروع يعمل محلياً، ولا توجد حاجة لإدخال مفاتيح أو نقل الصور لهذا التحسين. |

## 4. التعارضات التي يجب منعها

| الخطر | لماذا هو مهم | الحماية المطلوبة |
|---|---|---|
| تغيير لون أو نقشة الملابس | المنتج هو الحقيقة البصرية الأساسية | تحفظ المعالجة اللون، ويكون أي تحسين قابلاً للتراجع، مع اختبار قطعة سوداء وبيضاء ومنقوشة. |
| قص الرأس أو أطراف الشخص | هناك منطق حالٍ يحافظ على الشخص كاملاً | أي قاعدة قص أو تكبير جديدة تختبر صور الأشخاص الرأسية قبل قبولها. |
| عودة التمرير أو لوحة طويلة | المستخدم اشترط القالب الثابت والأدوات القصيرة | لا تضف شاشة إعدادات أو قوائم خلفيات طويلة؛ استخدم لوحة عائمة قصيرة فقط. |
| كسر الكاميرا أو قبول المعرض | رُفع التوافق مع MIME/امتدادات متعددة أخيراً | لا تلمس مسار قراءة الملف أو التفريغ عند تنفيذ تحسينات Canvas. |
| التباس المشاركة | أصبح للصورة فقط وواتساب مع النص زران منفصلان | التحسين البصري لا يضيف النص إلى الصورة ولا يغير الرسالة أو زر المشاركة. |
| تحميل ثقيل على الهاتف | ميزانية CSS الحالية عند حدها وحزمة البداية مضبوطة | أي أصل جديد يحمّل كسولاً من تخزين الأصول الخارجي؛ لا تنسخ الخلفيات داخل شجرة المشروع. |

## 5. الخطة الآمنة المقترحة

| المرحلة | التغيير المحدود | واجهة المستخدم | بوابة قبول |
|---|---|---|---|
| A — قياس أولاً | فحص محلي خفيف للدقة والحواف قبل التفريغ وبعده | رسالة قصيرة فقط عند وجود مشكلة واضحة | صور حقيقية: أسود، أبيض، منقوش، شخص؛ لا كسر للمعرض أو الكاميرا. |
| B — تحسين آمن | زر «تحسين سريع» داخل **تعديل الصورة** يستعمل إعدادات محدودة وقابلة للتراجع | لا أيقونة رئيسية جديدة | قبل/بعد، وتراجع، وثبات اللون والنقشة. |
| C — خلفيات قليلة | 6 خلفيات منتقاة من الحزمة، لا 25 دفعة واحدة | داخل أداة الخلفية الموجودة مع سحب أفقي | خلفية لا تغطي المنتج، أصل يحمل عند الاختيار، ولا زيادة في التمرير العمودي. |
| D — 2.5D اختياري | «استديو / عائم / منصة» فوق الظل والخلفية الحاليين | أداة عرض واحدة قصيرة **فقط بعد اعتماد المراحل السابقة** | لا قص، لا تغيير للقطعة، وسرعة مناسبة على هاتف. |
| E — قوالب العرض | قالب صور مصغرة منفصل واختياري | يؤجل حتى يثبت أنه لا يعقد تجربة القالب الأساسي | لا يدعي زوايا حقيقية ولا يفرضه على المستخدم. |

## 6. ما لا أوصي بتنفيذه الآن

لا أوصي بإعادة بناء غرفة الملابس، أو استبدال التفريغ المحلي، أو تفعيل 25 خلفية دفعة واحدة، أو إدخال 3D/360/AR، أو Image-to-3D، أو جعل تصنيف الفئات تلقائياً ومُلزماً، أو إضافة قوائم وأيقونات عديدة. هذه الخطوات تخالف طلب البساطة وقد تضيف مخاطر أداء وخصوصية من دون رفع مضمون للنتيجة.

## 7. التوصية النهائية

ابدأ فقط بالمرحلتين **A ثم B**: قياس حقيقي للجودة والحواف، ثم تحسين سريع داخل زر تعديل الصورة القائم. بعد نجاح صور المستخدم الحقيقية، نقرر إن كانت الخلفيات المختارة أو «عرض 2.5D» ستزيد القيمة فعلاً. لا يبدأ أي تنفيذ من الحزمة قبل هذا القرار، ولا تُنقل أصولها إلى المشروع تلقائياً.
